## 6. How to run an arc (the pipeline that shipped 0.18.x)

- Briefs: `COMMON.md` (rules for every author) + one `BRIEF.md` per arc with settled POSITIONS, territory (files the arc
  owns; cross-territory hunks minimal and listed), and localizing gates. Reviewer: `REVIEWER_COMMON.md` + a per-arc attack
  list. The batch-13/14/15 scaffolds are archived in the coordinator's memory (`archive/parallel13–15_*`).
- Author: Round 0 first (reproduce on the four arms — single, spilled, DAG, DAG-shuffled — against live PostgreSQL 17,
  with routing counters), then one mechanism per commit, `git commit -s` (Signed-off-by only), every gate proven to fail
  on revert, pins deleted as proofs, docs and ADRs in the same commit, REPORT with the census before → after.
- Reviewer: reproduce, never trust; every claimed gate reverted; the boundary attacked from both sides; a bounded model
  over a structural gap is a blocker (rule 11); rounds to CLEAN.
- Landing: fast-forward `main` to the reviewed tip (the second arc rebases onto the first), ONE battery on the combined
  tree (`battery_run.sh`: six lanes + both PostgreSQL oracle arms + gofmt), warm the pre-push hook cache, push, watch CI,
  then `postci.sh` closes the issues from the arc's own comment text, creates the release with the tag server-side, and
  publishes the notes. Bytes on the wire, wall, CPU and allocations are four co-equal metrics for perf work.
- The machine: 24 cores / 31 GB; `go test -p 2`; never `./...`; long runs detached with exactly ONE bounded waiter.
