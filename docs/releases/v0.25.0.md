## v0.25.0

A correctness and PostgreSQL compatibility release, with repairs to correlated subqueries, per-order top-N queries, recursive CTEs and file readers. Thirty issues close.

### Correlated subqueries retain their outer conditions

An outer reference in an inner JOIN’s `ON` inside an `IN` subquery now contributes to the result: a query selecting orders whose total exceeds a joined item’s amount returns the two matching orders, where v0.24.0 returned none. (#1232) A condition naming only the enclosing row also keeps its meaning: `EXISTS (SELECT 1 FROM orders z WHERE z.id = o.id AND o.total > 100)` filters the outer orders by their own total. (#1104)

An unqualified outer name is recognized when the body’s catalog relations do not supply it. (#1237) A reference in a clause the rewrite cannot preserve uses per-outer-row execution, with remaining unsupported forms listed in the [SQL reference](../sql-reference.md#subqueries).

A correlated body whose own WITH item shadows an enclosing WITH item is refused with `0A000`; renaming one of the items avoids that boundary.

### LATERAL top-N is per outer row

An equality-keyed correlated LATERAL applies `ORDER BY … LIMIT` and `OFFSET` to each outer row’s matching items. (#1019) For two orders with two items each, `ORDER BY amount DESC LIMIT 1` returns each order’s largest item; v0.24.0 returned just the largest item across both orders.

The qualified-star form, `SELECT s.*`, follows the same bound. An inequality-correlated bound or a bounded DISTINCT body whose output is not exactly the key is refused with `0A000`.

`EXISTS` with `LIMIT 0` selects no outer rows, a grouped body’s HAVING keeps only surviving groups, and an ungrouped aggregate inside EXISTS supplies one row even for an empty matching input. (#1238, #1274) A distributed window-to-join shape that needs the single-process pipeline is routed there; the underlying distributed work remains open as #1297.

### Recursive CTEs complete or fail

On the single-process pipeline, a 5,000-step `WITH RECURSIVE … UNION ALL` series returns all 5,000 rows, where v0.24.0 stopped at 1,001. (#1246) An error in a recursive iteration fails the statement instead of returning the rows accumulated before it. (#1041)

A still-producing recursion stops with `54000` at 1,000,000 iterations, and a working table larger than the memory budget raises `53200`. The seed supplies the column types and names, including for an empty result; a name published only by the recursive term is `42703`. (#1074)

An aggregate over the recursive reference is refused with `42P19`. Only a self-referencing item is recursive, so a non-recursive item in a WITH RECURSIVE list uses ordinary expression names. (#1193)

Native distributed recursive execution remains outside this change (#1042).

### The PostgreSQL catalog is queried by the engine

`pg_catalog` and `information_schema` support ordinary filters, joins, aggregates, sorting and limits over the server’s catalog. (#1251) The catalog supports psql’s `\d` family and metadata-query forms used by pgJDBC and SQLAlchemy.

The server reports PostgreSQL 17: `SELECT version()` names that major and the startup `server_version` parameter is `17.0 (Wadjet)`. The added SQL forms include `~`, `~*`, `!~`, `!~*`, byte-order `COLLATE`, `reg*` casts and `ARRAY(subquery)`.

A regex back reference or an unsupported collation is `0A000`. Statement Describe reports analysis failures such as a missing relation or invalid type combination. (#998)

A zero-row portal describes its columns (#999), and coded errors share their underlying message across the embedded and distributed servers (#1145).

### File readers keep file boundaries and reject malformed input

A JSON-array glob containing `[1,2]` and `[3]` as values of column `a` returns count 3 and sum 6, where v0.24.0 read only the first file’s two rows. (#1262) A multi-file Parquet glob reads each file through its own footer; the two-file input returns 11 rows instead of an invalid-magic error. (#1240)

A later Parquet file must supply the first file’s columns by name: a missing column is `42703`, and a different type is `42804`. CSV quoting follows COPY’s field rules: `""` is an empty string, an unquoted empty field is NULL, and short records or unterminated quotes raise `22P04`. (#1248, #1259)

Blank lines, mixed line endings and extra trailing empty fields continue to be read. A JSON array without its closing bracket, content after that bracket, or a non-object record raises `22P02` with input context.

A mixed boolean/number sample becomes text, and nested element types widen across the sample, preserving `[1.5]` after `[1]`. (#1260, #1261) Missing, unreadable and directory inputs are refused during planning, including EXPLAIN, with `58P01`, `42501` and `42809` respectively. (#1245)

### Binding rejects unsupported combinations and retains extensions

`SUM(text_column)` raises `42883` instead of returning NULL; `SUM('5')` is `42725`, and BOOL_AND over a number is `42883`. (#1249) MIN/MAX over a ROW is `42883`, and different stored ROW shapes in a fold or set operation are `42846`. (#1060, #1061, #1065)

A number compared with a boolean is `42883`; a searched CASE requires a boolean WHEN, and misplaced aggregates and windows receive the clause’s error class. (#1216, #1205) An ungrouped star in a grouped query is `42803`, while `SELECT 1 FROM t HAVING true` returns one group. (#1233)

Set-operation ORDER BY accepts result names and positions, retains the first arm’s selected qualified column, and rejects other qualifiers with `42P01`. (#1236) Text comparisons with integers, double precision, numeric, PORT, PROTOCOL, DURATION, UUID, IPv6 and CIDR remain accepted directly, in lists and in subqueries.

Set-operation membership retains those pairs only when every text arm has a matching typed `CAST(x AS TEXT)` origin; an arbitrary text-column body is `42883`. (#1073) DATE, TIMESTAMP and boolean keep direct and list text comparisons but refuse text subquery membership; REAL, BYTES, IPv4 and MAC text pairs are refused.

STRING_AGG keeps its non-text scalar renderings, including numbers, boolean, network values, UUID and DATE, while TIMESTAMP and containers are `42883` and BYTES is `0A000`. Plain numeric PERCENTILE_CONT and PERCENTILE_DISC calls remain accepted.

### An earlier comma sibling in ON: a v0.24.0 regression restored

`FROM a, b JOIN c ON a.id = c.k` answers again: the ON clause can name an earlier comma-separated FROM item, restoring the extension that v0.24.0 refused. (#617) A relation introduced by a later join remains out of scope.

### Reference

417 built-in scalar functions and 29 aggregate registry entries. The [differences page](../postgres-differences.md) records the retained extensions and refusal boundaries; the earlier-comma-sibling entry described as removed in v0.24.0 is back.

ADR-0021 records the correlated and recursive execution rules, ADR-0039 the reader rules, and ADR-0044 the system catalog.
